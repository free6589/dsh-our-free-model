# 06 复用指南：把「代理机制」搬到自己的项目

结论先说：这套仓库里**真正可复用的只有一层**——`src/forward.js` 的
`startForwardServer()`。它把「任意上游补全函数」变成「同时说 OpenAI 与 Anthropic 的
本地网关」。其余（免密车道指纹、十渠道登录、EAC 协付、自更新、热重载）都是特定上游的
适配层，复用价值取决于你是否要接同一个上游。

## 1. 唯一的复用缝：`complete()`

`startForwardServer()` 的契约（`src/forward.js:325`）：

```js
startForwardServer({
  config,        // () => { enabled, host, port, key }   每次请求都重新读，支持热改
  complete,      // (request, onChunk) => Promise<outcome>   ← 你只需要实现这个
  modelRows,     // () => [{ id, object:'model', owned_by, ... }]  /v1/models 返回体
  log,           // (msg) => void
  onTrace,       // ({ requestId, hop, path, stage, at, elapsedMs, status, outcome }) => void
  heartbeatMs,   // SSE 心跳间隔
  optimize,      // null | 本地提示词优化钩子
  health,        // () => ({ ok, service })
  handleRequest, // (req,res) => Promise<boolean>  返回 true 表示已自行处理（抢路由用）
}) => Promise<{ server, port, ... }>
```

`complete` 的入参与返回（`src/forward.js:830`、`862`、`646-668`）：

```js
// 入参 request
{
  model: 'deepseek-v4.1-flash',   // 已过 baseModelId() 归一
  openAi: { messages, tools, tool_choice, stream, max_tokens, reasoning_effort, ... },
  signal: AbortSignal,            // 调用方断开时已 abort，务必透传给上游 fetch
}

// 流式回调 onChunk，三种 chunk（forward.js:650-652 判定"有内容"用这三个）
{ type: 'text-delta',       text: '增量文本' }
{ type: 'reasoning-delta',  text: '思维链增量' }
{ type: 'tool-call-delta',  argumentsDelta: '{"a":1', /* + id/name 视实现 */ }

// 返回 outcome
{
  text: '完整正文',
  toolCalls: [{ id, name, arguments }],
  usage: { prompt_tokens, completion_tokens, total_tokens },
  truncated: true,                // 命中 max_tokens
  error: '错误消息',              // 有值即视为失败
  failure: { code, message },     // CODE 词表，见 00 分册错误码表
}
```

只要 `complete` 满足这四条，你就同时白拿了：OpenAI chat completions（含 SSE 与
tool_calls 重编号）、OpenAI Responses、Anthropic `/v1/messages`（含 content_block 事件序列）、
`count_tokens`、CORS、key 鉴权、SSE 心跳、断连取消、`x-ofm-request-id` 追踪。

## 2. 最小可跑实现（自己写一个上游，20 行）

```js
// my-gateway.mjs — 把任意 OpenAI 兼容上游包成网关
import { startForwardServer, generateKey } from './src/forward.js'

const KEY = process.env.OFM_KEY || generateKey()
const BASE = 'https://api.example.com/v1'
const UPKEY = process.env.UPSTREAM_KEY

async function complete(request, onChunk) {
  const res = await fetch(`${BASE}/chat/completions`, {
    method: 'POST',
    headers: { 'content-type': 'application/json', authorization: `Bearer ${UPKEY}` },
    body: JSON.stringify({ ...request.openAi, model: request.model, stream: true }),
    signal: request.signal,                    // ← 必须透传，否则断连不生效
  })
  if (!res.ok) return { text: '', toolCalls: [], error: `upstream ${res.status}` }

  let text = ''
  const toolCalls = []
  const usage = {}
  const reader = res.body.getReader()
  const dec = new TextDecoder()
  let buf = ''
  for (;;) {
    const { value, done } = await reader.read()
    if (done) break
    buf += dec.decode(value, { stream: true })
    const lines = buf.split('\n')
    buf = lines.pop() ?? ''
    for (const line of lines) {
      if (!line.startsWith('data:')) continue
      const data = line.slice(5).trim()
      if (data === '[DONE]') continue
      let ev; try { ev = JSON.parse(data) } catch { continue }
      const d = ev.choices?.[0]?.delta ?? {}
      if (typeof d.content === 'string' && d.content) {
        text += d.content
        onChunk?.({ type: 'text-delta', text: d.content })
      }
      if (typeof d.reasoning_content === 'string' && d.reasoning_content) {
        onChunk?.({ type: 'reasoning-delta', text: d.reasoning_content })
      }
      for (const tc of d.tool_calls ?? []) {
        const slot = toolCalls[tc.index ?? 0] ??= { id: tc.id, name: '', arguments: '' }
        if (tc.function?.name) slot.name = tc.function.name
        if (tc.function?.arguments) {
          slot.arguments += tc.function.arguments
          onChunk?.({ type: 'tool-call-delta', argumentsDelta: tc.function.arguments, id: slot.id, name: slot.name })
        }
      }
      if (ev.usage) Object.assign(usage, ev.usage)
    }
  }
  return { text, toolCalls: toolCalls.filter(Boolean), usage }
}

const { port } = await startForwardServer({
  config: () => ({ enabled: true, host: '127.0.0.1', port: Number(process.env.PORT ?? 8787), key: KEY }),
  complete,
  modelRows: () => [{ id: 'deepseek-v4.1-flash', object: 'model', owned_by: 'mine' }],
  log: m => console.error('[gw]', m),
})
console.log(`listening on 127.0.0.1:${port} key=${KEY}`)
```

## 4. 接第二个上游要改哪里

想在这套代码里加一个自有上游（而不是另起项目），改动面是封闭的四点：

1. `src/providers/registry.json` 加一条 provider 记录（id、base、能力、模型前缀）。
2. `src/providers/index.js` 的 `getProvider()` / `listProviders()` 能读到它。
3. `src/route/classify.js` 给新 provider 一个分类归属，否则路由不会选它。
4. `src/upstream.js` 的 `endpointFor()` / `gatewayHeaders()` 分支里加该上游的线缆形状。

**不要**动 `src/forward.js`：它只认 `complete()`，与上游无关。这条边界是整个仓库最值得学
的架构决定——网关层不认识任何上游。

## 5. 坑清单（按踩坑代价排序）

1. **`complete()` 必须透传 `signal`**（`src/forward.js:661`）。不透传 → 客户端断开后上游请求
   继续跑，白烧配额；`serveCompletion` 里三个断开信号（`req aborted` / `socket close` /
   `res close`）汇成一个 `AbortController`，别自己再造一套。
2. **chunk 类型只有三种**。`text-delta` / `reasoning-delta` / `tool-call-delta`。想加
   `image` 之类要先改 `forward.js:650` 的 `hasContent` 判定，否则首字节提交时机错。
3. **非流式也别信 `Content-Type`**。上游会在 `content-type: application/json` 下回 SSE 帧
   （`src/http.js` 头注释，issue #6 的教训）——按首字节 sniff，不按头。
4. **`tool_calls[].index` 必须从 0 重编号**。上游 block index 与 reasoning/text 共用，
   首个工具调用常是 2+，按 index 累积的客户端会得到带洞数组（`src/forward.js` 头注释，issue #20）。
5. **`/health` 故意在鉴权之前**（`src/forward.js:355`）。想加鉴权先想清楚：探活工具会因此挂掉。
6. **body 上限 8MB 硬编码**（`MAX_BODY_BYTES` `src/forward.js:43`）。长上下文/多图会撞上，
   改成可配置。
7. **LAN 中继与本地网关是两把 key**。本地 key 给本机，relay key 给局域网；relay 只转发
   白名单路径且带 `x-ofm-chan-relay-hop` 防环（`src/chan-relay.js` 头注释）。别把两把混用。
8. **loopback 绑定要解析后再绑**。`resolveLoopbackBind()` 先解析再 bind，防 hosts 文件把
   可路由地址混进来（`src/forward.js:395` 注释）。

由此确认的四条硬事实：

1. `startForwardServer()` **不需要 dsh 宿主**，直接 `node` 跑得起来——`src/forward.js` 只依赖 `node:http`/`node:crypto`/`node:net`/`node:dns`/`node:perf_hooks`。
2. 同一端口**同时**提供 OpenAI chat（流式/非流式）与 Anthropic messages，无需任何转译 shim。
3. `/health` 免鉴权、其余全部要 key，401 的错误信封是 OpenAI 形状。
4. `complete()` 只返回 `{text, toolCalls, usage}` 就能得到合法响应；`usage` 被原样透传到 `chat.completion.usage`。
