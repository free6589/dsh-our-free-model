# 01 入口与网关层

对象：`dsh-our-free-model` 2.5.9（`package.json:3`）。只读分析，全部结论按「文件:行号」给出；凡未在源码中直接读到、仅由结构推断的，均标「推测：」。

两条产品线共用同一套内核：

- **DSH 插件半身**：入口 `index.js`（2334 行），由 cordis 装配，向 `@deepseek-ai/dsh-llm` 注册 provider，并在 `webServer` 上挂 `/api/our-free-model`。
- **独立服务（standalone）**：入口 `packages/standalone/cli.mjs` → `service.mjs` → 同一个 `src/forward.js` 网关，不加载 cordis、不读 dsh 凭据（`packages/standalone/service.mjs:106`）。

两者共用 `src/core/runtime.js`（模型运行时 + 适配器）与 `src/forward.js`（OpenAI 兼容监听器）。

## 1. 装配链

### 1.1 cordis.patch.yml 改什么

`cordis.patch.yml` 全文只有一个 `insert` 操作，插入一个 loader 条目（`cordis.patch.yml:5-8`）：

```yaml
- insert:
    - id: our-free-model
      name: 'dsh-our-free-model'
      config: {}
```

- `id: our-free-model`：loader 条目的稳定 id，与插件导出 `name = 'our-free-model'`（`index.js:65`）同名。
- `name: 'dsh-our-free-model'`：必须是**裸包名**。文件头注释写明：一行 insert 即挂载 Host 半身；浏览器半身由 `package.json` 的 `dsh.client` 声明，并绑定在 name 为裸包名的那一行上，子路径行不会携带半身（`cordis.patch.yml:3-4`）。
- `config: {}`：交给插件 `apply(ctx, config)` 的空配置（`index.js:135`）。

装配只允许一个入口：被 `dsh.profile.bundles` 引用的包，其自带 patch 层自动生效；**两处同时注册会报 `duplicate loader entry id: our-free-model`**（`README.md:158-159`）。

### 1.2 package.json 的 dsh.bundle / dsh.client

```json
"dsh": {
  "bundle": { "patch": "./cordis.patch.yml" },
  "client": { "platform": "web", "immediately": true, "inject": [] }
}
```
（`package.json:56-63`）

- `dsh.bundle.patch`：声明本包的 bundle patch 文件路径，dsh 装包时读它并应用 §1.1 的 insert（`package.json:57-59`）。
- `dsh.client.platform: "web"`：浏览器半身只投递到 web 端（`package.json:61`）。
- `dsh.client.immediately: true`：客户端半身随宿主加载即注入，不等用户打开面板（`package.json:62`）。
- `dsh.client.inject: []`：客户端侧不声明依赖注入项，即不向内核索取额外前端服务（`package.json:63`）。

### 1.3 client.js 注入方式

- 导出映射：`"./client": "./client.js"`（`package.json:10`），并在 `files` 白名单内随包发布（`package.json:39-40` 段）。
- 形态：**手写 ModuleLoader bundle，无构建步骤**（`README.md:375`）；文件 6773 行、约 508 KB 的压缩产物（`wc -l client.js` = 6773）。
- 装载与热更：替换 `client.js` 后浏览器端由内核 client-hmr 自动重载（`README.md:596`）。
- 推测：`dsh.client` 的三字段由 dsh 宿主侧消费（本仓库内无读取方，`grep -rn "dsh.client" --include=*.js` 只命中 `package.json`），因此具体注入协议以宿主实现为准，本仓库只负责声明与产出 bundle。

### 1.4 Host 半身的入口契约

- `export const name = 'our-free-model'`（`index.js:65`）。
- `export const inject = ['llm']` —— **唯一硬依赖**（`index.js:107`）。注释明确：`webServer`、`timer`、`connection`、`attachments` 都不进 `inject`，缺了就降级而不是整插件 pending（`index.js:88-106`）。
- `export function apply(ctx, config)`（`index.js:135`）。
- `webServer` 通过嵌套 `ctx.inject(['webServer'], ...)` 后注册两条路由：`prefix /api/our-free-model`（`index.js:1358`）与 `exact /api/our-free-model/events`（`index.js:1362`）；注释说明 exact 优先于 prefix，故 SSE 由 hub 独占（`index.js:1359-1361`）。
- 生命周期清理：forward / relay / chanRelay / outletRelay 在 `ctx.effect` 的 dispose 中统一 close（`index.js:1394-1399`）。
- 数据目录（插件线）：`DSH_HOME` 或 `~/.dsh` 加 `our-free-model`（`src/store.js:24-30`）。

## 2. provider 注册

### 2.1 adapter/kernel.js 到底做什么

**它不是 provider 接口层**。全文件 51 行只导出一个函数 `resolveAttributionUserAgent(logger)`（`adapter/kernel.js:40-51`）：

1. `await import('@deepseek-ai/dsh-llm')`（`adapter/kernel.js:42`）；
2. 若模块导出 `attributionHeaders` 函数，取返回头里的 `user-agent` / `User-Agent`（`adapter/kernel.js:43-45`）；
3. 任何异常或形状不符都降级为字面量 `'deepseek-harness/0.1.7 (+https://github.com/deepseek-ai/deepseek-harness)'`（`adapter/kernel.js:46-50`）。

模块头注释说明它的存在意义：这是包内**唯一**允许命名 `@deepseek-ai/*` 的模块（审计门 §4.3「adapter 层外不允许 `@deepseek-ai/*` import」），其余源码只消费结构化 `ctx` 契约（`adapter/kernel.js:1-18`）。

调用点：`index.js:36` 导入，`index.js` 内在装配早期解析一次并把结果作为 `attributionUserAgent` 传给运行时（`index.js:409-418` 处的 `createModelRuntime({...})`，standalone 则直接传 `${PRODUCT}/${VERSION}`，`packages/standalone/service.mjs:240`）。

### 3.3 key 生成与 keyMatches 常量时间校验

- 生成：`generateKey()` = `` `ofm-${crypto.randomBytes(24).toString('base64url')}` ``（`src/forward.js:100-102`），注释强调「Not derived from anything user-visible」。
- 插件惰性铸造：`forwardKey()` 若 `settings.forwardKey` 为空则铸新值并 `flush()`（`index.js:553-560`）；LAN 中继用**另一把** `relayKey()`（`index.js:567-575`）；渠道包中继再用第三把 `chanRelayKey()`（`index.js:674-681`），三把互不复用。
- standalone 铸造：启动时 `existingKey` 非空则复用，否则 `generateKey()`，随后 `settings.update({ forwardKey: key })` + `flush()`，写盘失败即抛错（`packages/standalone/service.mjs:223-233`）。
- 校验链：`authorized(req, key)` → `keyMatches(bearerOf(req), key)`（`src/forward.js:679-681`）；`keyMatches` 先比 `byteLength` 再 `crypto.timingSafeEqual`（`src/forward.js:105-109`）；`bearerOf` 接受 `Authorization: Bearer <k>`（大小写不敏感前缀）与 `x-api-key` 两种携带方式（`src/forward.js:112-117`）。
- 空 key 一律拒绝：`if (typeof key !== 'string' || key === '') return false`（`src/forward.js:679-680`）。
- LAN 中继与渠道中继各自比对自己的 key：`keyMatches(bearerOf(req), settings.lanKey)`（`src/forward.js:538-541`）、`keyMatches(bearerOf(req), settings.lanKey)`（`src/chan-relay.js:122-125`）。
- 管理面另有一套常量时间比较 `matches()`（`packages/standalone/management.mjs:28-33`），用同一 `forwardKey` 做 Bearer 认证（`packages/standalone/management.mjs:120-125`）。

### 3.4 端口冲突重试

`bindForwardPort(server, {address, port, attempts, backoffMs, scan, log})`（`src/forward.js:281-322`），常量 `BIND_ATTEMPTS = 4`、`BIND_BACKOFF_MS = 150`、`BIND_SCAN = 10`（`src/forward.js:262-264`）：

1. `port <= 0` 或非有限值 → 直接 `listen(0)`，无回退（`src/forward.js:283-286`）。
2. 原地重试最多 4 次，指数退避 `backoffMs * 2 ** attempt`（`src/forward.js:288-298`）——覆盖「旧进程正在关闭 / portproxy 规则刚删」的几百毫秒窗口（注释 `src/forward.js:269-279`）。
3. 仍失败 → 向后扫描 `requested+1 .. requested+10`（且不超 65535）（`src/forward.js:299-306`）。
4. 全被占 → 兜底 `listen(0)` 取临时端口，「临时端口也好过没有监听器」（`src/forward.js:307-308`）。

`classifyBindError(error)`（`src/forward.js:219-235`）返回 `{kind, code, retryable, hint}`：

| code | kind | retryable | hint 要点 | 行号 |
| --- | --- | --- | --- | --- |
| `EACCES` / `EPERM` | `held` | 是 | Windows 上 0.0.0.0 监听（如 `netsh interface portproxy`）会让回环绑定报 EACCES 而非 EADDRINUSE | `src/forward.js:220-227` |
| `EADDRINUSE` | `in-use` | 是 | 端口被别的进程占用 | `src/forward.js:228-231` |
| `EADDRNOTAVAIL` | `unavailable` | 否 | 解析出的回环地址不在本机 | `src/forward.js:232-234` |
| 其它 | `unknown` | 否 | 空 | `src/forward.js:235` |

`bindFailure()` 把错误整形成设置页可展示的 `{code, kind, message, hint}`（`src/forward.js:239-242`）。

### 3.5 绑定地址的 loopback 强制

`resolveLoopbackBind(host)`（`src/forward.js:180-207`）：

- 空值 → `'127.0.0.1'`；IPv6 字面量去掉方括号（`src/forward.js:181-182`）。
- 是 IP 字面量：必须是 `::1` 或 `127.*`，否则抛错（`src/forward.js:183-186`，`isLoopbackIp` 在 `src/forward.js:210-212`）。
- 是主机名：`dns.promises.lookup(..., {all:true, verbatim:true})`，**任一**解析结果非回环即抛错；返回解析后的 IP 而非原始拼写（`src/forward.js:188-206`）。注释记录原因：hosts 文件或企业 DNS 把 `localhost` 指到可路由网卡时，字符串检查会一直通过而把免密额度送给整个子网（issue #19，`src/forward.js:167-179`）。

### 3.6 持久化字段

- 插件 settings（`settings.json`，0600 由 store 层保证，`src/store.js` 注释见 `README.md` 架构段）：`forward.{enabled,host,port}`、`forward.lan.{enabled,port}`、`forwardKey`、`forwardLanKey`、`chanGateway.relay.{enabled,host,port,key}`（`src/store.js:167-183`、`index.js:553`、`index.js:567`、`index.js:674`）。

- 上游失败分类由 `failureReply()` 决定状态码、`x-should-retry: false` 与 `retry-after`（`src/forward.js:159-169`）。
- 请求体上限 8 MiB（`src/forward.js:43`、`:124-135`）；非 JSON → 400；`null`/数组/标量 → 400（`src/forward.js:136-147`）。

两个线上卫生规则（注释在 `src/forward.js:16-28`，实现在 `createToolWire` `src/forward.js:744-803`）：`tool_calls[].index` 从 0 重编号；命中 fingerprint 诱饵名且调用方未声明的工具调用被抑制，若整轮只剩这种调用则回 502 说明（`src/forward.js:977-990`）。SSE 静默心跳 15 s（`src/forward.js:707`、`:716-728`）。

### 5.3 lanEnabled / lanPort

- CLI 语义：`--lan` 开启并**保存** LAN 推理中继，`--no-lan` 关闭并保存，`--lan-port` 只保存期望端口、不单独开启（`packages/standalone/cli.mjs:12-14`）。落到 `settings.standaloneLanEnabled` / `standaloneLanPort`（`packages/standalone/service.mjs:226-229`）。

- 启停协调 `reconcileRelay()` 串行化（`:160-208`）：主开关关、LAN 开关关或已停止 → `closeRelay()`；端口变了才重绑（`:165-170`）；`standaloneLanKey` 为空或**等于 `forwardKey`** 时重铸（`:172-175`）；若管理面绑在非 `127.0.0.1`（IPv6 回环），额外起一个只做推理、无管理路由的 `startForwardServer({host:'127.0.0.1', port:0})` 作为中继目标（`:176-187`）；中继本体固定 `host:'0.0.0.0'`、`lanKey: standaloneLanKey`、`localKey: forwardKey`（`:189-197`）；失败时只记 `relayError` 文本，不让服务起不来（`:201-205`）。

### 5.4 isLoopbackHost 规则

`isLoopbackHost(value)`（`src/trust.js:31-39`）：

1. `'::1'` 裸 IPv6 直接判真（URL 解析器要求方括号，这里额外放行，`src/trust.js:36`）。
2. 否则用 `authorityOf(raw, 'http')` 解析，命中白名单 `LOOPBACK_NAMES = {'127.0.0.1', '[::1]', '::1', 'localhost'}` 才为真（`src/trust.js:23`、`:37-38`）。
