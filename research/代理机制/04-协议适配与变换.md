三处题面假设与代码不符，先点名，后文按代码写：

1. **adapter 契约里没有 `generate`，也没有 `abort`**。`grep -n generate src/adapter.js` 无输出；唯一产出方法是非流式化的 `stream()`（`src/adapter.js:162-190`）。取消走 `options.signal` + 异步迭代器的 `return()/throw()`，非流式只是"把流折叠成一个对象"（`src/core/completion.js:74-80`、`src/anthropic.js:684-700`）。

## 1. provider 契约

### 1.1 契约的成立方式：结构化鸭子类型

`src/adapter.js:4-6` 写明：`registerAdapter` 是**调用这些方法来校验**，不做 `instanceof`，所以本插件不 import 任何版本钉死的 adapter 基类。挂载点只有一处：

```js
// src/index.js:423
const registration = ctx.llm.registerAdapter([ROUTE_MAIN, ROUTE_REGION], adapter)
```

两条 route 由**同一个实例**发布（`src/adapter.js:8-15`）：`our-free-model`（当前出口能用的）与 `our-free-model-region`（当前出口被网关拒的）。理由在注释里：picker 严格按 provider route 分组，没有第二个分组字段；空组会被 client 丢掉，所以 VPN 用户只看到一组。route 常量与标题见 `src/adapter.js:36-42`。

`adapter/kernel.js` 是包内**唯一**允许命名 `@deepseek-ai/*` 的模块（`adapter/kernel.js:1-12`），且只取一个 `attributionHeaders()`（`adapter/dsh-llm.d.ts:8-10`），失败降级为字面 UA（`adapter/kernel.js:44`）。也就是说本插件对内核的依赖面是 1 个函数，不是 adapter 基类。

### 1.4 重试策略是"完整对象"，不是片段

`src/adapter.js:68-72` 的注释是本文件最贵的一条经验：0.1.5/0.1.7 内核把这个对象**原样存盘**、不跑 policy resolver，退避调度器从顶层读 delay 字段；把 delay 塞进 `backoff` 子对象会让每个延迟变 `NaN`，durable session log 拒收，于是"可恢复的瞬时失败"变成"整回合中止"。

因此：`mode:'normal'`、`maxRetries:2`、`retryableCodes:['EMPTY_RESPONSE','SERVER','TIMEOUT','TRANSPORT']`、`initialDelayMs:700`、`maxDelayMs:8000`、`jitterRatio:0.2`。**`RATE_LIMIT` 与 region 码被故意排除**（`:78-83`）：region 拒绝是出口属性不是瞬态故障；本线 429 带**增长型** retry-after，两次自动重试把每个配额墙变成三堵墙、同一回合付三次钱（issue #13）。重试判定实际发生在 `src/adapter.js:642`，且要求"已有交付内容或有工具调用"才走内核重试。

### 1.5 一次回合的执行骨架（含 abort 与计数）

1. `runStream` 分流 combo / 单模型（`src/adapter.js:199-206`）；combo 的提交规则是"首个承载答案的 delta 之前全部可弃"（`commitsAnswer`，`:796-810`），reasoning delta **故意不算提交**（`:223-240` 注释 + `:796-806`）。
2. `runSingle` 每次请求前重建 payload：`buildPayload`（`:712-748`）→ 可选 `temperature`/`stop`（`:390-393`）→ 声明式 efforts 的 merge patch（`:404-407`）→ sealed 线加一句 pacing hint（`:408`、`SEALED_PACING_HINT` `:681-684`）→ **token savers 最后跑**（`:419`，保证字节数描述的是真正上线的 body）。
3. 指纹重命名只对自由线做：`sealed || kilo || aggregate ? new Map() : applyFingerprint(...)`（`:440`）。
4. 请求超时与 abort 双保险：`remainingMs = max(1, policy.totalTimeoutMs - 已耗时)`（`:444`），续写回合再 `min(policy.maxContinuationMs, remainingMs)`（`:446`），定时器 `unref`。
5. 计数：**每次 attempt** 一条 `recordUsage`（`record`，`:481-511`），字段 `{at,model,effort,ok,input,output,reasoning,cacheRead,decodeTokens,ttftMs,decodeMs,origin:'harness',recoveryId,attempt,elapsedMs,recoveryAttempt?,noUsage?,warnings?,savings?}`；**每回合**一条 `recordTurn`（`finishTurn`，`:374-390`，字段 `{at,model,ok,recovered,attempts,origin}`）。用量在 `collectUsage` 里跨 attempt 累加（`:357-372`），并且一旦某 attempt 的 input 不可信就整体归零 input、只保留 output（`trustedOutcome` `:345-355`，让宿主用本地估算）。
6. abort 的收尾：三处都产出 `usage` + `{type:'finish', reason:{kind:'aborted'|'error', failure:{code}}}`（`:418-424`、`:575-583`、`:625-640`），`finally` 里 `controller.abort()` 并 `await request`（`:655-680`）。
7. 错误形状：`toFailure`（`:754-774`）只携带白名单字段并逐个校验（message / code / 100-599 的整数 status / 正的有限 `providerRetryAfterMs`），因为宿主把 `LlmFailure` 直接写进 durable 事件、该日志拒收非无损 JSON 往返的值（Error 实例、`NaN`、显式 `undefined`）——一条坏 failure 比一条稀疏 failure 严格更糟。

## 2. Anthropic ↔ OpenAI 映射表

`src/anthropic.js` 是**纯编解码器**：无 socket、无定时器、无文件、无随机（`src/anthropic.js:11-14`），id 与时钟由调用方给（`state.messageId`、请求自带的 `model`），所以帧渲染是确定性的。端点本体在 `src/forward.js:1166-1297`（`messagesEndpoint`），路由注册在 `src/forward.js:379-386`。

### 2.1 请求方向：Anthropic Messages → 内部（harness）形态

入口 `fromAnthropicRequest(body)`（`src/anthropic.js:224-321`），与 `src/core/completion.js:89-140` 的 `fromOpenAiMessages` 同构：每行变 `{role, content:[…]}`，assistant 行放 `tool-call` 块，工具结果变一等公民 `role:'tool'` 行。

| Anthropic 请求字段 | 内部形态 | 行号 |
|---|---|---|
| `system`（字符串或 text 块数组） | 扁平化成**单个字符串**，块间 `\n\n` | `flattenSystem` `:91-100` |
| `messages[].role = 'system' \| 'developer'` | 提升进 `system`（不报错），`system = system + '\n\n' + text` | `:246-253` |
| `content` 为裸字符串 | 包成 `[{type:'text', text}]` | `:237-239` |
| `text` 块 | `{type:'text', text}`（空串丢弃） | `:294-296` |
| `image` + `source.type='base64'` | `{type:'image', attachment:{attachmentId: dataURL, mediaType, bytes:0, width:0, height:0, url: dataURL}}` | `harnessImage` `:116-122` |
| `image` + `source.type='url'` | 同上，但 `attachmentId: 'url:'+url.slice(0,64)`、`mediaType` 硬编码 `image/png` | `:123-129` |
| `tool_use`（assistant） | `{type:'tool-call', id, name, arguments: JSON.stringify(input ?? {})}` | `assistantBlocks` `:164-176` |
| `tool_result` | **独立** `role:'tool'` 行：`{content, toolCallId, source:{kind:'tool',callId}, isError?}`，`is_error` 只在 true 时出现 | `:272-286` |
| `tool_result.content` 为块数组 | 只取 `text` 与 `image`，其余丢弃 | `toolResultBlocks` `:133-147` |
| `thinking`（assistant 历史） | `{type:'reasoning', text}` | `:178-181` |
| `redacted_thinking` | **丢弃**（账号绑定的不透明密文，无法分辨有效/过期） | `:157-159`、`:34` |
| `tools[].input_schema` | 扁平 `{name, description, parameters}` | `:305-311` |
| `tools[].name` 为空 | 跳过该工具 | `:306-308` |
| `thinking` | `reasoningEffort`：`disabled`→`'disabled'`；`budget_tokens ≥ 16384`→`deep`；`≥4096`→`balanced`；否则 `light` | `BALANCED_AT/DEEP_AT` `:69-70`、`reasoningEffortFor` `:199-210` |
| `max_tokens` | `maxTokens`；`≤0` 视为未设（`undefined`），因为 adapter 的预算计算把非正值当"无上限" | `:313-315` |
| `temperature` | 原样 | `:316` |
| `stream` | `parsed.stream = body.stream === true` | `:319` |
| `stop_sequences` | **无映射，丢弃** | `:313-321` 字段全集不含 |
| `messages` 空 / 无可转换行 | 返回 `{error}`，不发上游（上游必 400） | `:294-297`、`:228-230` |

`thinking` → effort 的阈值是**圆整数**而非梯级本身（`:57-68` 注释）：`4096` 表示"默认"而不是"deep"，所以 `DEEP_AT = 16384` 必须 ≥ 两倍 balanced 梯级。返回的 id 必须是 `src/effort.js` 真梯级，因为 `resolveLevel` 对未知 id 静默回落到 `balanced`——编一个层级名等于得到一个永不上线的预算（`:186-198`）。

### 2.2 响应方向：上游 SSE → Anthropic 事件序列

入口 `anthropicFrames(chunk, state)`（`src/anthropic.js:455-608`），每个 chunk 返回**帧字符串数组**，由调用方直接 `res.write`（`src/forward.js:1270`）。`state` 由 `newMessageState(messageId, model)` 每流播种一次（`src/forward.js:1301-1309`）：`{messageId, model, started:false, finished:false, blockIndex:0, openBlock:null, openIndex, toolSlots:Map, inputTokens:0, outputTokens:0, stopReason:null}`。

| harness chunk | 发出的 Anthropic 帧 | 行号 |
|---|---|---|
| （首个 chunk 前） | `event: message_start`，`usage.input_tokens = state.inputTokens`，`output_tokens: 0` | `:459-471` |
| `text-delta` | 若未开则 `content_block_start`（`{type:'text',text:''}`）+ `content_block_delta`（`text_delta`） | `:477-484`、`openStreamingBlock` `:350-359` |
| `reasoning-delta` | `content_block_start`（`{type:'thinking',thinking:''}`）+ `content_block_delta`（`thinking_delta`） | `:485-492` |
| `tool-call-delta` | 名字已知才 `content_block_start`（`tool_use`）+ `input_json_delta`；名字未知则把参数碎片攒进 `slot.held` | `:493-514`、`openToolBlock` `:377-394` |
| `block-end`(tool-call) | `content_block_stop`；从未开过的块则在此时用 `block.arguments` 整体补发 start+delta+stop | `:515-552`、`closeToolBlock` `:396-403` |
| `block-end`(text/reasoning) | 关闭当前文本/思考块 | `:519-524`、`closeStreamingBlock` `:342-348` |
| `usage` | **不发帧**，只更新 `state.inputTokens/outputTokens`（Anthropic 把 input 放 message_start、output 放 message_delta） | `:553-561` |
| `finish` `stop` | `message_delta{stop_reason:'end_turn'}` + `message_stop` | `:562-607` |
| `finish` `max-tokens` | `stop_reason:'max_tokens'` | `:590-596` |
| `finish` `tool-calls`，或任一 tool 块曾开过 | `stop_reason:'tool_use'`（`hasToolBlock` 兜底） | `:590-596`、`hasToolBlock` `:412-415` |
| `finish` `error` / `aborted` | `event: error`（经 `forwardFailure` 包装）+ `message_stop`，**不发** `message_delta`（那会让 stop_reason 谎称"正常结束"） | `:570-588` |

块纪律的三条硬规则（`:437-453` 注释 + 实现）：

1. `message_start` 只在首个 chunk 前发一次，input 用 state 里已有的值（跑过 `countTokens` 的调用方可预置），真实值在 `message_delta` 里再报一次（`:592-597`）。
2. 文本/思考块**同时只有一个**，异类 delta 先关旧的（`openStreamingBlock` `:350-355`）。
3. 工具块例外：每个由自己的 `block-end` 关闭，所以并行调用可以并发流；如果为了开新块而关旧块，会把一次调用的 JSON 劈成两个同 id 块，客户端执行两次（`:443-451`）。

`state.finished = true` 在 `finish` 分支**第一句**就置位（`:563-569`）：端点若在流已自关之后再补一个 `message_stop`，严格客户端按协议错误拒收（`src/forward.js:1288-1293`）。

### 2.3 非流式与计数

- `anthropicMessage(outcome, {model,id})`（`src/anthropic.js:661-690`）：内容顺序 thinking → text → 每个 call 一个 `tool_use`；`stop_reason` 规则是"上限截断优先于工具调用"（`truncated` → `max_tokens`，否则有 call → `tool_use`，否则 `end_turn`，`:667-670`）。thinking 块**不带 `signature`**——这一侧不存在有效签名，空串是对客户端的谎（`:652-659`）。
- `foldAnthropicOutcome(outcome, chunk)`（`src/anthropic.js:721-796`）：与 `src/core/completion.js:174-194` 的 `foldForwardOutcome` 是双胞胎；tool call 按 harness 块 `index`（`slot`）合并，`block-end` **先按 slot 匹配**（按 id 匹配会把一次调用折成两次，产生一个空 id + 截断参数的幽灵 `tool_use`，`:741-766`）。
- `parseInput`（`src/anthropic.js:629-637`）：无法解析的参数变 `{}`，原文**不回显**（Anthropic 的 `input` 类型是对象，没有字段能装坏文本；空 input 在执行期会响亮失败，模型可重试）。
- `countTokens(body)`（`src/anthropic.js:799-834`）：4 字符=1 token，图片固定 1024，工具框架 8/个，序列化 schema 也按 4:1，基础 16（防除零）。**是估算不是分词器**（`:782-798`），端点 `/v1/messages/count_tokens` 直接回它（`src/forward.js:383-386`）。

## 3. 消息归一化

`src/messages.js` 是"harness 消息词表 ↔ 三种线上形状"的唯一投影层；反向（provider 事件 → chunk）在 `src/stream.js` 的 `readStream`。

### 3.1 内容归一

- `blocksOf(content)`（`:33-45`）：字符串→`[{type:'text'}]`（空串→`[]`）；数组里 `text`/`input_text`/`output_text` 统一成 `text`；其余对象原样保留。注释点明动机：forward listener 里 OpenAI 调用方合法地发裸字符串（`:26-31`）。
- `textOf(blocks)`（`:19-24`）：只拼 `type==='text'`，**用 `\n` 连接**（不是 `\n\n`；`\n\n` 只用于 system 块合并，见 `flattenSystem`）。
- `imageDataUrl(block, resolveImage)`（`:50-53`）：`block.offloaded === true` 直接返回 undefined（图已外置，不带 URL）；否则 `resolveImage(attachment) ?? attachment.url`。所有 `image-dropped` 告警都从这里分叉。

### 3.2 多模态（image_url）

- Chat 线：`{type:'image_url', image_url:{url}}`（`:184`、`:208`）。
- Claude 线：`claudeImageBlock(url, warnings)`（`:252-266`）**只接受 data: URL**，且 media type 必须在 `IMAGE_MEDIA = {image/png,image/jpeg,image/webp,image/gif}`（`:16`）里，否则丢弃并告警——远程 URL 在这一线没有表示法。
- Responses 线：`{type:'input_image', image_url: url}`（`:331-398` 内，`input_image` 分支）。
- 工具返回的图：`role:'tool'` 只能装文本，所以图片被**挪到紧随其后的 user turn**（`followUp` 队列，Chat `:184-217`、Responses `:357-388`）；Claude 线则内联进 `tool_result.content`（`:268-329` 内）。这是 `read_image` 结果不丢的唯一原因。

### 3.3 工具调用配对

`toolResultsOf(message)`（`:65-88`）同时认两代内核形状：V4 的 `role:'tool'`（content **就是**结果）与 pre-V4 的 `user` 消息里 `tool-result` 包装块。只读一种会让每个用工具的回合把结果丢在上游之外——模型察觉不到，于是反复重发同一个调用直到用户喊停（`:56-64` 注释）。

`repairToolPairing(messages)`（`:90-166`）在**投影之前**跑（`src/adapter.js:334`），一次修好三条线：

- 收集所有"已应答"的 callId（`:97-104`）。
- 无 call 可配的 `tool` 行直接丢（空 `tool_call_id` 在上游是整回合 400，`:128-135`）。
- assistant 行里**无名**的 tool-call 当未应答处理并丢弃（issue #92：空名调用曾被宿主回 `Error: unknown tool ""`，于是它成了"已应答"，永久留在历史里，之后每个回合每个模型都 400，`:136-152`）。
- 被丢调用的结果随后自然通不过 kept-calls 检验，跟着一起消失（`:110-126`）。
- 整段清理是幂等的：什么都没丢时原对象透传（`:155-160`）。

### 3.4 role 合并与空内容

- Claude 线 `push(role, blocks)`（`:275-283`）：**同 role 连续行合并**进同一条 wire turn。原因：内核自己的 Messages adapter 把结果并到前一轮，而 pre-V4 历史把工具应答写成独立 user 消息，连续两条 user 正是 `messages` 线拒收的形状。
- Chat 线不合并 role，但保证"并行调用的所有结果都排在 image/user 内容之前"（`followUp` 收尾，`:217`）。
- 空内容：assistant 行既无 text 又无 call 就整行跳过（`:219-221`）；Claude 线 `content.length === 0` 跳过（`:317`）；Claude 的 `tool_result` 空内容补 `[{type:'text',text:'(no output)'}]`（`:291`）。
- V4 `tool` 行的 `continue`（`:294-296`、`:362`）：它的 content **已经**全进了 `tool_result`，继续往下会把同一段文本（以及整段 base64 图）再追加一次，上游按两倍计费。
- `toToolDefs(tools, style)`（`:400-424`）三种拼法：`claude` → `{name,description,input_schema}`；`flat` → 顶层 `{type:'function',name,description,parameters}`；`chat` → `{type:'function',function:{…}}`。同时接受扁平和 `{type:'function',function:{…}}` 两种入参（`:404-410`，否则 forward listener 的调用方会静默丢掉全部工具）；名字按 `MAX_TOOL_NAME_LEN` 截断（`src/upstream.js`）。
- `needsVision(messages)`（`:426-428`）：`offloaded` 的图不算。

## 4. 本地优化与 token-saver

两套东西互不相干：`local-optimize` 在 **Anthropic 入口**拦掉五类"不值得问模型"的请求（省一次调用）；`token-saver` 在 **payload 落地前**改请求体（省同一调用的 token）。前者是短路，后者是压缩。

### 4.1 local-optimize：五种本地答案

评估顺序 `OPTIMIZATIONS = ['quota','prefix','title','suggestion','filepath']`（`src/local-optimize.js:26`），注释给了理由：最便宜最常见的先跑，配额探针（一个整数 + 一个子串）在需要解析命令行的检测器之前短路（`:21-25`）。

| 种类 | 命中判据 | 本地答案 | 记账 usage | 行号 |
|---|---|---|---|---|
| `quota` | `max_tokens === 1`（或 `'1'`）且唯一 user 文本含 `quota` | `'Quota check passed.'` | 10 / 5 | `:307-316` |
| `prefix` | 文本含 `<policy_spec>` 且含 `Command:` | `extractCommandPrefix(command)` 的结果 | 100 / 5 | `:318-327` |
| `title` | 无 tools，system 含 `title` 且（含 `sentence-case title` 或"JSON 字段"式措辞） | `'Conversation'` | 100 / 5 | `:329-339` |
| `suggestion` | 任一 user 文本含 `[SUGGESTION MODE:` | 空文本 | 100 / 1 | `:341-350` |
| `filepath` | 文本含 `Command:` 与 `Output:`，无 tools，且 user 或 system 提到 filepaths | `<filepaths>…</filepaths>` 块 | 100 / 10 | `:352-371` |

跳过条件（`firstAnswer` `:382-397`、`tryOptimizations` `:413-430`）：

- 全局开关 `enabled` 或该种类开关为 false 即跳过（`enabled[kind] !== false` 才跑）。
- `singleUserTurn(request)`（`:91-100`）要求**恰好一条 user 且无 assistant/tool 行**——历史一长就不再是"本地可答"的请求。
- `hasTools(request)`（`:102-105`）为真时 title/filepath 直接放弃（带工具的一律走上游）。
- 非 Anthropic Messages 形状（比如 OpenAI 请求体）根本不进来：入口只有 `messagesEndpoint`（`src/forward.js:1189-1215`）。
- `extractCommandPrefix`（`:196-232`）遇到 `` ` `` 或 `$(` 直接返回 `'command_injection_detected'`（`:198`）——不执行、不猜测，把字符串当答案回给调用方。

关闭方式与作用域：`settings.localOptimize = {enabled, quota, prefix, title, suggestion, filepath}`（默认全 true，`src/store.js:225`）；UI/HTTP 通过 `publicLocalOptimize`/`optimizeConfig`（`src/index.js:2094-2103`、`:537`、`:1724-1728`）读写。

计费影响：命中即**不发上游请求**，返回体里的 usage 是上表那些固定小数（`toMessagesResponse` `:432-446`，id 为 `msg_<uuid>`）；流式模式下用同一套 `anthropicFrames` 渲染三帧（text-delta → usage → finish），所以客户端看不出这是本地答案（`src/forward.js:1200-1215`）。因此它省的是**整次调用**，不是几个 token。

### 4.2 token-saver：两段流水线

`src/token-saver/index.js:1-21` 的注释定死了范围：① prompt shaping（改系统提示的语气），② tool-output compaction（rtk，压工具输出）。**没有第三段**——不做响应侧裁剪、不做历史摘要。

配置（`saverConfig` `:42-56`，默认值在 `src/store.js:194-198`）：

```js
{ enabled: section.enabled !== false,          // 总闸，默认 true
  rtk: section.rtk !== false,                  // 默认 true（机械压缩，不动语气）
  caveman: String(prompts.caveman ?? 'off'),   // 默认 off
  ponytail: String(prompts.ponytail ?? 'off') }// 默认 off
```

默认"rtk 开、prompt 关"是刻意的：prompt 族会改变助手的**声音**，机械压缩不会（`:33-41` 注释）。

`applyTokenSavers(payload, wire, config)`（`:69-100`）就地改 payload，先 prompt 后 rtk，返回 `{prompt, rtk, saved, bytesBefore, bytesAfter, notes}`；任一段抛错只写 `notes`（`prompt-failed:…` / `rtk-failed:…`），整条 fail-open——省 token 的功能绝不能成为请求失败的原因。

#### 4.2.1 prompt shaping

- 两族：`caveman`（7 档：off/lite/full/ultra/wenyan-lite/wenyan/wenyan-ultra，`src/token-saver/prompts.js:31`）、`ponytail`（4 档，`:34`）。`cavemanPrompt`/`ponytailPrompt` 对 `off` 与未知档返回 `null`（`:204-210`、`:216-222`）。
- 注入文本带幂等标记：`<!-- ofm-token-saver -->` … `<!-- /ofm-token-saver -->`（`src/token-saver/inject.js:37-40`）。`injectSystem`（`:65-90`）的 reason 是 `injected | already-injected | no-text | shape-not-recognised | inject-failed`——`already-injected` 走整段精确匹配（`contentHasRegion`/`hasRegion`），所以重复跑同一 payload 不会叠加两段。
- 三条线各自落点：`chat` 挂到（或新建）system 消息（`injectChat` `:201-233`）；`messages` 写进 `system` 字符串或块数组，且**插在最后一个 `cache_control` 块之前**（`injectMessages` `:283-330`，注释在 `:301-310`）——插到缓存标记之后会让整段前缀失效，等于每次多付一次全量 input；`responses` 优先写 `instructions`，没有才退回 `input`（`injectResponses` `:353-374`）。
- 反向：`stripInjected`（`:92-112`）按标记剪除，`hasInjected`（`:114-143`）只读判断；`messages` 线剥完若 system 为空会 `delete payload.system`（`:332-362`）。

#### 4.2.2 rtk（机械压缩工具输出）

- 入口 `compressRequest(payload, wire, options = true)`（`src/token-saver/rtk/index.js:258`），分派到 `compressChatPayload`（`:281`）/`compressMessagesPayload`/`compressResponsesPayload`；**只改 `role:'tool'` 的 content，不动 assistant 的 `tool_calls.arguments`**（`:288-298`）——改参数等于改模型已做出的决定。
- 单块决策 `compressText(text, stats, shape)`（`:190-219`）：`bytesIn < MIN_COMPRESS_SIZE(500)` 或 `> RAW_CAP(10MB)` 直接放过（`:194-197`，常量 `constants.js:23`、`:32`）；`autoDetectFilter` 按前若干字符认形状（`:199`）；`safeApply` 跑过滤器（`:205`）；最后一道保险是**输出非空且严格更小**，否则原样返回（`:207-212`）。
- 12 个过滤器（`constants.js:130-142`）：git-diff / git-status / git-log / grep / find / ls / tree / dedup-log / smart-truncate / read-numbered / search-list / build-output；别名 `rg→grep`、`fd→find`（`registry.js:44-52`）；`build-output` 故意不在 registry 里，只能被自动识别选中。
- 日志 `formatRtkLog(stats)`（`:225-231`）输出 `[RTK] saved NB / MB (P%) via [filters] hits=N`。

#### 4.2.3 关闭与计费影响

- 关闭：`tokenSaver.enabled=false` 全关；`tokenSaver.rtk=false` 只关压缩；`tokenSaver.prompts.{caveman,ponytail}='off'` 只关语气（`src/store.js:194-198`）。整段可逆——`stripInjected` 能剪掉历史里已注入的提示（`inject.js:92-112`）。
- 计费：payload 变小只会让**上游报的 prompt token 变小**（推测：本线按上游 usage 计，插件不二次计价）；本地只把字节数记进 stats 的 `savings` 桶（`bytesBefore/bytesAfter/saved/blocks/calls/promptCalls`，`src/store.js:432-444`），**不回写 `record.input`**——`record()` 的 input 来自上游 usage（`src/adapter.js:485-500`），`savingsFields` 只是附加字段（`:807-824`）。所以面板上的"saved N bytes"是请求体瘦身量，不是账单差额。

### 5.2 生成：`scripts/build-manifest.mjs` 一次写两份

`node scripts/build-manifest.mjs`（`scripts/build-manifest.mjs:1-43` 头注释即用法）：

1. 取 `package.json` 的 `files` 列表 + `package.json` 自身（`:79`），目录递归展开、跳过 `node_modules` 与点开头（`:90-99`）。
2. 每个文件按 **LF 归一化后的字节**算 `{path, size, sha256}`（`:101-110`；归一化在 `scripts/lib/published-bytes.mjs`，与 git blob 一致）。
3. 写 `feed/manifest.json`：`{version, base:'../', publishedAt, notes, files, signature?}`（`:134-141`），`base:'../'` 让文件 URL 落在仓库根。
4. 写 `catalog/integrity.json`：`{version, algorithm:'sha256', files}`（`:180-186`）——**同一个 builder 写两份**，所以不可能互相矛盾（`:176-179` 注释）。实测结构见 `catalog/integrity.json:1-8`（version 2.5.9 / sha256 / files[]）。
5. 降级保护：已发布版本 ≥ 目标版本时拒绝，`--force` 才过（`:113-128`，按段比较，注释记着旧实现用字符串比较把 1.9.0 判成比 1.10.0 新）。

### 5.3 签名与校验

- 算法：**Ed25519**，`signManifest`/`verifyManifestSignature`/`PINNED_MANIFEST_PUBLIC_KEY` 全在 `src/updater.js`（`build-manifest.mjs:46` 引入）。
- 私钥**不在仓库**：`--key <pem>` 或 `OFM_MANIFEST_KEY`（`:52-56`）；没有私钥时脚本拒绝写未签名 manifest（`:166-170`）。
- 密钥自检：签名一个探针对象、用**钉死的公钥**验一遍，不匹配就退出（`:59-66`）——用错密钥签出的版本会让所有用户的升级路径砖掉。
- 签名对象是 `parseManifest(manifest)` 的规范化输出，不是原始对象（`:141-143`），所以未来加字段不会改签名。
- `--check`（`:150-164`）：零写入，比对 `feed/manifest.json` 与 `catalog/integrity.json` 各自描述的 `files`（`describeDrift` `:190-207`，逐文件比 size 再比 sha256，还查"清单里有但已不发布"），并复验已提交 manifest 的签名；不一致即非零退出。这条检查的动机写在 `:30-40`：URL 从仓库取新文件、哈希却是旧的，等于让每个用户升级失败。
- `catalog/provenance.json` 是**人工维护**的溯源声明（不是脚本生成）：subject（id/version/源码 revision）、license（MIT）、`upstreamRuntime`（唯一内核依赖是 `adapter/kernel.js`，无版本钉死）、`vendoredChannelPack`（第三方插件包，含上游 revision 与许可证）、`distribution`、`integrity`（指向 manifest 与 integrity，并写明 LF 归一化）、`mojobox`（明确 `recordInstalled:false`、`artifactDigest:null`，注释说"不得编造"）。
- `catalog/dsh-plugin.json` 是 dsh-plugin **0.15** 生态记录：`facets.host.entry = index.js`、`apiVersion v1alpha1`、`x-ecosystem-packaging` 三条自述（adapter 隔离由 `scripts/catalog-test.mjs` 强制、`distribution=managed` 降级开关、integrity/provenance 出处）。

## 6. 统计与自检

### 6.1 职责边界：写侧在 adapter，读侧在 stats.js

| 模块 | 职责 | 不做什么 |
|---|---|---|
| `src/core/completion.js` | 把**外部请求**折成 `adapter.stream()` 的 GenerateOptions，再把 chunk 折成 `{text, thinking, toolCalls, usage, truncated, error}` | 不重试、不落盘、不计时、不做可用性判定 |
| `src/adapter.js` | 真实调用 + 计时 + 每 attempt `recordUsage` / 每回合 `recordTurn` | 不渲染面板、不聚合天/模型维度 |

`completion.js` 的四个出口：`routableModelIds(snapshot)`（`:6-12`，ROUTE_MAIN 的成员，`exposeRegionModels !== false` 时并上 ROUTE_REGION）、`publicModelRows(snapshot)`（`:14-31`，OpenAI `/v1/models` 形状，附 `context_window`、`x_ofm_efforts`、`x_ofm_effort_default`）、`createForwardCompletion({adapter,state,signal})`（`:33-83`，aborted→503、未知模型→404、`AbortSignal.any([request.signal, signal])`、截断时丢弃参数解析失败的工具调用）、`fromOpenAiMessages`/`foldForwardOutcome`（`:85-194`）。

### 6.2 stats 的字段

写侧一条 `recordUsage` 落到三处：日桶 `days[dayKey]`、终身 `models[id]`、样本环 `samples`（`src/store.js:345-420`）。日桶里每模型累计 `{input, output, reasoning, cacheRead, calls, failed, ttftMs, ttftSamples, decodeMs, decodeTokens}`（`:351-368`），`decodeWindow` 决定这次测量能否进 `tps` 分子分母（`:355`、`:366-367`）。样本行额外带 `effort`、`origin`、`truncated`、`noUsage`、`recoveryId`、`attempt`、`elapsedMs`（`:382-400`）——注释说这条是为了让"那个回合消失了"的报障有东西可查（issue #10）。

`buildStats(stats, catalog)`（`src/core/stats.js:4-98`）输出：

- 顶层：`requests`、`requestFailures`（+`requestFailuresEstimated`）、`logicalEstimated`、`turns`、`failedTurns`、`recoveredTurns`、`days`（时间序列）、`models`（行数组）、`samples`（最近 200）、`savings`（含 `percent`、`summary`）、`grand`（`{input,output,reasoning,calls,failed,turns,failedTurns,recoveredTurns}`）。
- 每模型行：`{model, name, input, output, reasoning, cacheRead, calls, failed, ttftMs, ttftSamples, decodeMs, decodeTokens, turns, failedTurns, recoveredTurns, tps, avgTtftMs}`；`tps` 只在 `decodeMs >= MIN_DECODE_MS` 时算，否则 `null`（`:62`）——短样本除出来的数字是噪声，不是速度。
- 逻辑回合（combo 链）与物理调用分开：链本身以链 id 记 turn，链上每跳以自身 id 记 usage，所以"一条链 3 次失败 1 次成功"在面板上既看得到 1 个成功回合，也看得到 3 条失败调用。
- `savings` 汇总 `{bytesBefore, bytesAfter, saved, blocks, calls, promptCalls, percent, summary}`（`src/store.js:432-449`、`src/token-saver/index.js:105-148`）。

### 6.3 `model-test.js` 的自检判据与超时

`measureModelTest(stream, now)`（`src/model-test.js:9-44`）——**只有"非空、正常收尾、无工具调用"的答案才算通过**（`:8` 注释）：

| 判据 | 失败码 | 行号 |
|---|---|---|
| 出现 `tool-call-delta` 或 `block-end` 的 tool-call 块 | `CODE.server`（"unexpected tool call"） | `:22-23` |
| `finish.upstreamFinish` 不在 `stop`/`end_turn`/`stop_sequence` | `CODE.server` | `:27-29` |
| `finish.reason.kind !== 'stop'` | 沿用上游 failure 的 code，缺省 `CODE.server` | `:30-31` |
| 流读完但从未 `finish` | `CODE.empty` | `:34` |
| `text.trim()` 为空 | `CODE.empty` | `:35` |
| 正常 | 返回 `{totalMs, latencyMs, ttftMs, outputTokens, reasoningTokens, tokensPerSecond, sample, text}` | `:37-44` |

TTFT 的起算点是**首个非空 delta**（文本或推理都算，`:15-19`），`windowTokens(usage, sawReasoning)`（`src/stream.js:454-458`）决定分母：推理没流出来时把 reasoning token 从分子里扣掉，否则会把整段思考时间算到答案上、报出 349 tok/s 这种假速度（`:444-453` 注释）。

超时是**整轮**的，含 combo 链的重试：`MODEL_TEST_TIMEOUT_MS = 300_000`（`:6`），`runModelTest` 用 `Promise.race([measureModelTest(...), aborted])` + 一个 `setTimeout` 在 `timeoutMs` 后 abort 控制器（`:46-73`），`finally` 里清定时器、摘监听、并在已 abort 时主动 `iterator.return()`（`:68-72`，注释：adapter 的 `return()` 会先 abort pending 的 `next()`）。

可用性判定 `modelAvailability(id, snapshot, listed)`（`:76-92`）：手动测量与自动探测分开存，取**较新的**那个（比较 probe 的 `startedAt` 与 manual 的 `at`，`:85`），`stale` 行（旧出口的判定）直接忽略；`listed` 为真时根本不用 probe 行——被上游清单点名的模型，健康度归清单那一轮管（`src/core/runtime.js:293-300` 注释）。

## 7. 复用手册

### 7.1 接入一个自带协议上游所需的最小接口（8 个，缺一不可）

以"我要再挂一条 `channel:'mine'` 的线"为目标，按依赖顺序：

1. **catalog 行**——必须有 `id / name / wire / vision / reasoning / contextWindow / maxOutput`，`wire` 决定解析器（`src/catalog.js:211-250` 是模板，`kiloEntryOf` `:522-552` 是"从上游行翻译"的模板）。少了 `contextWindow`，`resolveModel` 会退到 131072 的兜底（`src/adapter.js:126-134`），预算按错的上限算。
2. **`channel` 标记 + `isXxxEntry()`**——adapter 只按 `entry.channel` 分派（`src/adapter.js:324-326`），并据此跳过指纹重命名（`:440`）。
3. **poster 函数**——签名固定为 `(deps, payload, signal, onData) → Promise<response>`，只要把 SSE 的 `data:` 行喂给 `onData`（参照 `postSealedTurn` `:706-724`、`postKiloStreamed`、`postAggregateStreamed`；自由线的 `postStreamed({path, body, session, attributionUserAgent, signal, onData})` 在 `:471-497`）。
4. **wire 解析器**——`readStream(lines, wire, renameMap, now, opts)`（`src/stream.js:466+`）目前认 `'chat'|'responses'|'messages'`。新协议要么先映射成这三者之一，要么在 `readStream` 里加分支；**不要**绕开它自己 emit chunk，因为块跟踪器（`mintToolCallId`、断名保护、`brokenToolCall`）都在里面。
5. **请求投影器**——`toChatMessages` / `toClaudeMessages` / `toResponseInput` 三选一（`src/messages.js:163-398`），加一条新的就在同文件加一个同签名的函数并在 `buildPayload` 分派（`src/adapter.js:712-748`）。
6. **finish token 映射**——`finishReason(token)`（`src/stream.js:437-441`）；新协议若是"显式 done 事件 + 无 finish token"，要在解析器里自己给出等价 token，否则截断会被当成正常结束。
7. **usage 映射**——`mapUsage(usage)`（`src/stream.js:224-260`）要求**非负有限数**：`cached_tokens` 缺失必须先补 0 再相减，否则 `inputTokens` 变 `NaN`，durable session log 直接拒收（`:210-223` 注释）。
8. **错误码**——`CODE`（`src/http.js`）里的 `server/transport/empty/aborted/credential/region`；新上游的 4xx/5xx 要映射到这几个，否则重试策略（`src/adapter.js:73-88`）和"是否降级为 region"（`code === CODE.region` → `onRegionBlocked`）都不会触发。

可选但强烈建议：`applyFingerprint`（若上游按工具名指纹风控）、`applyTokenSavers`（省 token）、`effortPatch`（若上游声明了真实思考档位）。

### 7.2 三协议合并映射表（一张表看全）

| 语义 | Anthropic Messages | OpenAI Chat | OpenAI Responses | 内部（harness） |
|---|---|---|---|---|
| 系统提示 | `system`（字符串或块数组） | `messages[0].role='system'` | `instructions`（优先）或 input 首项 | `options.system` 或前导 `role:'system'` 行 |
| 用户文本 | `content:[{type:'text'}]` | `{role:'user', content:'…'}` | `input:[{role:'user',content:[{type:'input_text'}]}]` | `{role:'user', content:[{type:'text'}]}` |
| 图片 | `{type:'image',source:{type:'base64',media_type,data}}` | `{type:'image_url',image_url:{url}}` | `{type:'input_image',image_url}` | `{type:'image', attachment:{…}}` |
| 工具定义 | `{name, description, input_schema}` | `{type:'function', function:{name,description,parameters}}` | 顶层扁平 `{type:'function', name, description, parameters}` | 扁平 `{name, description, parameters}` |
| 模型发起调用 | `{type:'tool_use', id, name, input}` | `tool_calls:[{id, type:'function', function:{name, arguments}}]` | `{type:'function_call', call_id, name, arguments}` | `{type:'tool-call', id, name, arguments:'<json>'} ` |
| 工具结果 | user 里的 `{type:'tool_result', tool_use_id, content, is_error?}` | `{role:'tool', tool_call_id, content}` | `{type:'function_call_output', call_id, output}` | `{role:'tool', toolCallId, content}` |
| 思考内容 | `{type:'thinking', thinking}` | `reasoning_content` | 加密 reasoning item（本插件丢弃） | `{type:'reasoning', text}` |
| 思考强度 | `thinking:{type,budget_tokens}` → light/balanced/deep | `reasoning_effort` | `reasoning:{effort}` | `options.reasoningEffort` |
| 流式结束 | `message_stop` + `message_delta.stop_reason` | `finish_reason` | `response.completed` / `incomplete` | `{type:'finish', reason:{kind}}` |
| 停止原因 | `end_turn` / `max_tokens` / `tool_use` / `stop_sequence` | `stop` / `length` / `tool_calls` | `stop` / `max_output_tokens` / `function_call` | `stop` / `max-tokens` / `tool-calls` |
| 用量 | `usage:{input_tokens,output_tokens}`（start + delta 分两次） | `usage:{prompt_tokens,completion_tokens,prompt_tokens_details}` | `usage:{input_tokens,output_tokens,input_tokens_details}` | `{inputTokens,outputTokens,reasoningTokens?,cacheReadTokens?}` |

三条不变式（跨协议通用，改任何一条都要重读本节）：

1. **工具结果必须是独立行**，不能塞回 assistant 行——三条线的上游都会因此把结果当"模型自己说的"。
2. **调用与结果必须一一配对**，无名的调用当未应答丢弃（`src/messages.js:136-152`，issue #92）。
3. **图片只走白名单媒体类型**；Claude 线还要求 data: URL（`src/messages.js:16`、`:252-266`）。

## 8. 未确认项
