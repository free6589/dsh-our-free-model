# 07 上游闸门逆向笔记（免密免费车道）

这一分册记录的是**这套仓库最有情报价值、也最易失效**的部分：`opencode.ai` 免费车道的
客户端指纹闸门。代码里的每一行都是实测结论，不是设计选择。换上游即作废。

## 2. 判定方法（可复用的逆向套路）

这套方法本身比结论更值得记：

1. **确认闸门是客户端指纹而非账号/配额**：本机跑官方客户端（`opencode-ai@1.19.0`），
   `opencode run -m opencode/cat-jam-free` 可用 → 说明与账号无关。
2. **抓真包**：自签 CA + `NODE_EXTRA_CA_CERTS` 做 TLS 中间人，把官方客户端指到本地，
   读到真实请求路径与头集。
3. **单变量对照**：用普通 Node `https` 逐字节重放，每次只删/改一项，记录 200/403。
4. **矩阵化**：工具维度单独做矩阵（`bash` 单独 / `read` 单独 / 两者空 schema / 两者带 property /
   大小写变体），一次定位到"定义逐字比对"这一层。
5. **区分身份检查与限流**：同一出口 IP 上，官方客户端字节通过而新建升序 id 403 →
   是身份校验，不是 IP 限流。

## 3. 注入策略（v2 的坑）

v2 的 `read`/`shell` 是**真工具**（描述与 schema 来自官方客户端），模型会真的去调。
v1 靠"must not be used"的桩描述压住，v2 只能靠提示词压：

- 注入时补一句 `Do not call the ... tools; they are placeholders that do nothing.`
  （`placeholderNote()`，`upstream.js:~125`）。
- 措辞是实测选出来的：写成"不可用"会让模型连调用方自己的 `Read`/`Bash` 一起拒绝；
  "占位、请用别的工具"才既压住注入项、又不误伤调用方工具。
- 调用方同名但定义不同的工具 → 改名成 `<name>_client[N]`，响应侧再还原，
  历史里的同名调用一起改名（`docs/free-lane-wire.md` 修正段）。
- 指向诱饵工具的工具调用在网关侧被**抑制**（`src/forward.js` 头注释：issue #20），
  否则调用方会收到一个自己从未注册的工具。

## 4. 配额语义

- 配额单位是**会话**，不是请求：`429 FreeUsageLimitError` 时换新 session 只会更糟，
  所以 session id 按会话稳定缓存（`sessionForConversation()`）。
- 实测 `retry-after` 可达 ≈12 小时。
- `REGION_BLOCKED` 与配额无关，出口一变即恢复，所以喂给可用性探测而不是重试
  （`src/http.js:30` 注释）。

## 5. 失效信号：怎么知道这套又崩了

按这个顺序排查，一次定位：

```bash
# 1. 车道还活着吗（不需要 key，看 /health 与模型列表）
curl -s http://127.0.0.1:PORT/health
curl -s http://127.0.0.1:PORT/v1/models -H "Authorization: Bearer $KEY" | head -c 300

# 2. 直接打上游清单端点，看是否连 403
curl -s -o /dev/null -w '%{http_code}\n' https://opencode.ai/inference/v1/models

# 3. 一次性对话，读 error.type
curl -s https://opencode.ai/inference/v1/chat/completions \
  -H 'authorization: Bearer public' \
  -H 'user-agent: opencode/latest/2.0.26/cli' \
  -H 'content-type: application/json' \
  -d '{"model":"deepseek-v4.1-flash","messages":[{"role":"user","content":"ping"}]}' | head -c 500
```

`error.type` 对照：

| error.type | 含义 | 动作 |
| --- | --- | --- |
| `FreeTierError` | 客户端指纹被拒（UA/头/工具定义/会话形状任一不符） | 对照第 1 节逐项复核；这是**车道级**拒绝，重试无用 |
| `RegionError` | 出口地区被排除 | 换出口，别重试 |
| `FreeUsageLimitError` | 会话配额用尽 | 等 `retry-after`，或换车道 |
| `ModelError` / "Model is unavailable" | 该 id 不再路由 | 刷目录，剔除该模型 |

## 6. 什么时候别抄这套

- 换成你自己的上游（有正常 API key）→ 第 1 节整张表全部作废，不要带入。
- 上游只要"像浏览器"而不是"像某个具体客户端"→ 用常规 UA 池即可，别做逐字 schema 比对。
- 涉及绕过第三方服务的使用限制时，先确认对方 ToS 与你自己的合规边界；本分册只记录
  代码事实与逆向方法论，不构成使用建议。
